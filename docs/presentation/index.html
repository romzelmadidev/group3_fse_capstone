API Gateway on :8080

  • Verifies the JWT signature, then checks the token id against a Redis blacklist, so a logged-out token stops working at once.
  • Per-user rate limits: 10/s, burst 20, on auth and accounts. 20/s, burst 40, on transfers and risk. Over the line gets 429.
  • An Idempotency-Key is held for 10 minutes, so retries over patchy mobile data can't double-post.

Who is signing in

  • Access tokens live 15 min. Refresh tokens live 7 days and rotate on every use.
  • The refresh cookie is SameSite=Strict and scoped to /api/v1/auth.
  • 5 wrong passwords lock the account for 15 minutes.
  • Email OTP: 5 min lifetime, 60 s resend cooldown, 5 attempts, generated with SecureRandom.
  • An expired session gets one silent refresh, then a clean return to login. Checked every 30 s and on app resume.

Which phone is asking

  • The first phone is bound with OTP and becomes the primary device.
  • A new phone needs approval from the primary before it can sign in.
  • Sign-in is refused on rooted phones, unlocked bootloaders and developer mode.
  • Runtime signals feed the risk engine: hooking, emulator, screen sharing, remote access apps, active calls.

What is being sent

  • Every transfer is scored by the risk engine before core banking sees it.
  • Biometric challenge at ₱50,000 or score 60. The amount is re-checked when the signature comes back.
  • 10-minute cooling-off at ₱250,000, with funds reserved, not sent.
  • Scam advisories must be acknowledged before the transfer continues.

Where it is kept

  • Passwords and PINs are stored only as hashes.
  • KYC images sit in a private kyc-vault container, reachable only through 5-minute signed links.
  • A separate PostgreSQL audit vault keeps the mutation journal apart from the ledger.
  • Datadog APM and OpenTelemetry trace 100% of requests across services.
